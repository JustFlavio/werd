# Werd 0.1.0-alpha.3

A Windows x64 prerelease focused on guided project setup, project tools and safer
daily operations. macOS and Linux remain development targets; this release does
not provide installers or validated support for them.

## What's new

- Home and navigation center on projects. Databases, cache, mail, storage and
  search appear inside the project that uses them. Shared infrastructure controls
  remain in advanced settings.
- Project preparation identifies missing PHP/Node, application/frontend
  dependencies, encryption keys, environment values, local addresses and HTTPS.
  Home shows incomplete preparation, and the main project action guides users to
  the missing steps before opening the application.
- The creation wizard explains starter kits and prepares missing Node.js when
  npm is enabled. Importing summarizes the selected PHP version and keeps
  overrides under Customize. Both flows continue to the project page.
- Live frontend status, controls and logs are visible in the project overview.
  Live updates can be enabled for the next project start.
- Review and explicitly apply proposed `.env` connection changes, with private
  original backups outside the project and protection against stale previews.
  Standard imports leave the environment file unchanged until review; the advanced
  APP_URL checkbox opts into an immediate update.
- Back up PostgreSQL, MySQL and MariaDB databases from the project or CLI. Restore
  to a new database without overwriting an existing destination. Switching the
  project's database connection remains an explicit operation.
- Connect coding assistants to Werd's own read-only MCP server for project,
  runtime, service and diagnostic information. No Herd installation is required.

## Reliability and security

- Preserve existing PostgreSQL data, validate Redis requirements and avoid
  duplicate engines after rejected creation attempts.
- Improve concurrent runtime installation, project-state writes and cleanup of
  managed processes, including completed database tools and Windows descendants.
- Update dependencies, replace a withdrawn Rust package and remove sensitive data
  from test diagnostics. A remaining GTK dependency advisory is documented in
  `docs/research/base-workflow-review.md`; it is not presented as resolved.

## Before installing

- Close Werd from the system tray before replacing the installed application.
  Installer upgrades stop the daemon and its managed processes while replacing
  binaries; Werd's data directory is retained.
- Node/runtime downloads and creating a new project require internet access.
  Local HTTPS requires explicitly trusting Werd's local CA.
- Frontend dependency installation currently supports npm. Projects using another
  package manager must install their dependencies with that manager in a terminal.
- Werd runs Vite directly using the project's configuration; custom npm dev
  scripts/hooks and custom hot-file locations remain outside this managed flow.
  With live updates off, the application uses its last built frontend assets.
- pgvector on Windows still requires Visual Studio Build Tools. Queue workers,
  scheduler supervision, Reverb, structured Laravel logs, dumps and Xdebug setup
  remain roadmap work. This alpha does not claim full Herd feature parity.

## Validation boundaries

Automated checks and browser fixtures cover project preparation and navigation,
but do not replace clean-machine native installer, upgrade, HTTPS trust and live
Laravel acceptance tests. Server status describes running processes; preparation
checks local files/configuration rather than application HTTP/database health.

Tauri updater signatures are distinct from Windows Authenticode signatures.
Local test installers are not published to the signed preview update channel.
